\section{Stabilizer formalism as digital logic, and the Steane kernel reconstruction}\label{app:reconstruction}

\subsection{Stabilizer codes as Boolean logic}\label{app:formalism}

A Pauli error on \(n\) qubits is fully characterised by two binary vectors \(E=(x_{\rm err},z_{\rm err})\in\mathbb{F}_2^n\times\mathbb{F}_2^n\), where \(x_{\rm err}[q]=1\) iff qubit \(q\) has an \(X\) or \(Y\) error and \(z_{\rm err}[q]=1\) iff it has a \(Y\) or \(Z\) error (a \(Y\) error sets both bits). A stabilizer group with \(m\) generators is described by a parity-check matrix \((H_X\mid H_Z)\in\mathbb{F}_2^{m\times2n}\), and the syndrome is \(s=H_Z\cdot x_{\rm err}\oplus H_X\cdot z_{\rm err}\pmod2\): each syndrome bit is one XOR-reduction over a subset of error bits, which is exactly what an FPGA LUT6 tree computes natively. Decoding is a lookup or graph search returning a correction \((x_{\rm corr},z_{\rm corr})\) such that the residual error commutes with every logical operator; for a distance-3 code with \(m\le8\), the decoder is a \(2^m\)-entry ROM of width \(2n\) that fits in one or two BRAM18K blocks. Logical-error detection is one more XOR-reduction, over the residual error masked by a logical operator's support. The entire pipeline is therefore a handful of XOR trees plus one memory read, which is why all three kernels in this paper synthesise to a small combinational footprint (Section~\ref{sec:results}).

\subsection{Steane kernel reconstruction}\label{app:steane-recon}

No \texttt{steane\_qec\_kernel.cpp} implementing the three-mode architecture described in Section~\ref{subsec:steane} could be recovered from the archive this revision was built from. The kernel evaluated in this paper (\texttt{rtl/steane713/src/steane\_qec\_kernel.cpp} in the accompanying repository) was written from scratch against the algorithmic description in Section~\ref{subsec:steane}, and its logic was verified, before synthesis, against a Python model exercising every single- and double-qubit error pattern.

That verification process surfaced a genuine defect in the description it was built from. A literal reading of the union-find-inspired mode's description -- ``each qubit counts how many of its adjacent check nodes are active; if the count is odd, the qubit is included in the correction'' -- computed as a raw parity count against the \emph{entire} active-syndrome set, does not correctly decode single-qubit errors on this code's Tanner graph: for a syndrome equal to a single column of \(H\) (a genuine weight-1 error), roughly four of the seven qubits satisfy the raw parity test and are spuriously included. The corrected implementation instead computes, for each qubit \(q\), whether its full column \(H_{\rm col}[q]\) equals the syndrome exactly -- algebraically the same test the LUT and MWPM-inspired paths use, consistent with the observation that, for this specific code, one growth round of a peeling decoder collapses to exactly this equality test rather than a raw adjacency count. With this correction, the union-find-inspired mode passes the same exhaustive weight-1 and weight-2 checks as the other two modes (Section~\ref{subsec:res-correctness}).

A second property of this code's structure is worth recording because it bears on the ``the three modes handle weight-2 syndromes differently'' claim made about an earlier version of this kernel: for every pair of Steane data qubits \((i,j)\), \(H_{\rm col}[i]\oplus H_{\rm col}[j]\) equals \(H_{\rm col}[k]\) for some third qubit \(k\), a consequence of the \([7,4,3]\) Hamming code's linear structure. This means every weight-2 \(X\)-only error's syndrome is indistinguishable, at the syndrome level, from a weight-1 error on qubit \(k\), and all three decoder modes alias to the same (incorrect) single-qubit correction for every such event, verified exhaustively across all 21 qubit pairs. The three modes do not differ in how they handle weight-2 syndromes on this code; they agree, on the wrong answer, which is the expected behaviour of any decoder operating past a code's guaranteed distance and is not evidence against any one mode's implementation.
